# 写入与核对

此流程用于用户已请求的一次发布或指定区域修改。仅创建 skill、检查连接或转换格式时，不要往真实文档写测试内容。

## 准备正文

把选定的正文保存为 UTF-8 Markdown 文件，使用绝对路径。保存与调整输入文件使用正常的文件编辑工具。去掉仅用于聊天显示的 `:::writing` 外层标记；代码块围栏属于正文，不能误删。若用户指定了精确正文，不额外加摘要、免责声明或发布记录。

使用当前飞书工具 `docx_v1_document_convert`：

```json
{
  "data": {"content_type": "markdown", "content": "用户选定的正文"},
  "useUAT": true
}
```

无原生工具时执行辅助脚本 `convert 正文文件绝对路径`。转换结果包括 `blocks` 与有序的 `first_level_block_ids`。`blocks` 本身顺序不可靠，必须根据第一层 ID 和每个块的 `children` 重建树。

在首个写请求前遍历整棵树，确保没有漏失、重复引用或无法处理的类型。普通文本、标题、列表、代码、引用、待办与分隔线可以直接创建；表格需要下面的单元格流程。图片、附件、合并单元格或特殊组件需要另外的上传/编辑能力，不能静默丢弃、伪造图片上传或把格式转换成功当作素材上传成功。若超出当前能力，向用户说明并取得替代方案后再发布。

## 当前工具结构限制

本机使用官方 `@larksuiteoapi/lark-mcp`。已验证版本 0.5.1 的 `docx_v1_documentBlockDescendant_create` 输入结构没有暴露子孙块的 `block_id`、`children` 和 `table_cell` 字段。直接提交转换结果可能被工具校验丢掉树结构。因此，本版本使用 `docx_v1_documentBlockChildren_create` 逐层创建；不要为了简化流程直接调用该子孙接口。

版本升级时可以读取真实工具结构重新判断，不能假定限制仍然存在。辅助脚本只开放已验证的只读工具、创建子块、更新块和批量更新；不包含删除和子孙创建。

## 追加内容块

从 Wiki 节点解析得出真实 `document_id` 后，读取根块 `docx_v1_documentBlockChildren_get`，分页读取全部直接子块。根 `block_id` 是 `document_id`。读取时可以使用 `document_revision_id: -1`。记录原有子块 ID 顺序，用于确认没有覆盖原内容。

查询或写入的 JSON 用辅助脚本 `call 工具名 参数文件绝对路径` 执行；写请求再加 `--write`。输入文件一次代表一个请求，不通过 shell 拼接正文。辅助脚本强制 `useUAT: true`，避免意外切换到应用身份。

按 `first_level_block_ids` 顺序取根块，并为每个块生成可写负载：

- 不提交转换用的 `block_id`、`parent_id`、`children` 或 `comment_ids`；后端返回的真实 ID 才用于后续定位。
- 保留 `block_type` 和对应正文结构，例如 `text`、`heading1`、`bullet`、`ordered`、`code` 等及其文本样式。创建时也不要传入文本样式中的评论 ID。
- 按工具实际输入结构构造负载；不要把转换结果中所有字段原样塞入写请求。
- 每批可取不超过 30 个直接子块作为保守分批策略；这不是对官方最大批量的声明。一个请求失败或结果未知时停止后续写入。

示例（`document_id`、`block_id` 必须替换为已解析的真实 ID；索引替换为当前末尾位置）：

```json
{
  "path": {"document_id": "真实文档ID", "block_id": "真实文档ID"},
  "params": {"document_revision_id": -1, "client_token": "本次请求唯一UUID"},
  "data": {
    "index": 1,
    "children": [
      {"block_type": 3, "heading1": {"elements": [{"text_run": {"content": "标题"}}]}},
      {"block_type": 2, "text": {"elements": [{"text_run": {"content": "正文"}}]}}
    ]
  },
  "useUAT": true
}
```

每次写入前按实际根子块数量计算末尾索引；若检测到其他人同时改动，重新读末尾，不使用旧位置。每批结果核对后再继续。记录响应 `children` 中真实 ID 与原转换 ID 的对应关系。

有嵌套列表、引用容器等子树时，在父块创建成功后，以该父块的新 ID 创建它的直接子块，再依次处理更深层级。不要把嵌套子项全部铺平成根段落。

## 表格

Markdown 表格对应 `block_type: 31`；其 `children` 指向 `block_type: 32` 的单元格块。

1. 创建表格时只提供 `table.property.row_size` 和 `column_size`；不传 `table.cells`、`merge_info`、转换用的单元格 ID 等只读字段。当前子块创建结构不能保证原列宽或表头外观，因此不要承诺像素级复刻。
2. 由后端生成单元格，读取新表格块的 `table.cells` 或有序单元格 `children`，必要时用 `docx_v1_documentBlock_get` 读取。确认数量等于行数乘列数。
3. 按原单元格顺序与新单元格顺序建立对应，逐个填入其原始正文子块，保留单元格中的文字与换行。不要自己创建 `block_type: 32`。
4. 若单元格有后端生成的空段落，可读取它，并使用 `docx_v1_documentBlock_patch` 更新该空段落，然后追加剩余段落；先查询该工具的实时输入结构。不要为了清理空段落自行增加删除权限或删除已有内容。

## 指定内容修改

用户要求改已有内容时，先分页读取块并定位唯一目标，再读取 `docx_v1_documentBlock_patch` 或 `docx_v1_documentBlock_batchUpdate` 的实时结构，更新授权范围内的块。不以追加全文代替用户要求的原位修改。目标不唯一且选择会影响其他内容时先询问。

当前连接没有配置删除工具。要求清空全文或覆盖整页时不要擅自改 MCP 配置、扩大范围或循环清空内容，说明限制并请用户决定是否改为更新指定区域或追加新版。

## 回执、失败与核对

辅助脚本的写入回执位于参数文件旁 `.feishu-write-receipts`，不含正文和凭据。`client_token` 是写请求的幂等标识，不是登录令牌。同一幂等标识已有回执时脚本拒绝再次调用。

- `api_confirmed`：接口确认执行成功，仍需回读；不是最终的内容核对结论。
- `api_rejected`：接口明确拒绝；根据错误检查登录、权限或参数。
- `pending` 或 `unknown_check_document_before_retry`：进程中断或请求状态不明。先回读文档/相应父块，检查该批文字与创建结果；不自动发出新幂等标识重复追加。不能安全确定是否写入时，报告不确定性并暂停发布。

如果原生 MCP 没有生成本地回执，则在工作文件中记录每批的唯一 `client_token`、成功块 ID 与进度，执行同样的防重复策略。不得声称幂等标识可永久防止跨任务重复。

完成后按新 ID 读取内容块，核对文本与重要样式，核对嵌套顺序和表格行列/单元格内容，并确认原根子块仍在。不要只凭 `rawContent`、块数量或版本号声称精确核对成功。

只有这次发布的所有预期内容均读取一致后才报告完成。部分成功则提供文档链接、已确认的范围与未完成部分；不能用“已写入”掩盖遗漏。使用可点击的文档链接交付，不输出密钥、访问令牌或完整连接配置。
