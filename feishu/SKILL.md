# 飞书文档写入

把用户选定的内容真正写入飞书文档，并读取结果核对。仅讨论、预览或检查连接的请求不授权写入。

## 内容与目标

- 内容优先使用用户指定的文本、文件或上一份明确的输出；不要顺便发布其他对话、内部推理、工具日志或凭据。只调用 `$feishu` 而没有可确定的内容时，询问要写入哪一份结果。
- 用户本次提供的文档链接优先；没有新链接时，可使用本机连接配置中的 `defaultUrl`。未配置默认链接且用户未给目标时，先询问链接，不猜测目标。一次性使用其他文档不改变默认配置。
- 默认追加到文档末尾，保留原内容。只有用户明确要求时才修改指定段落或区域；不要把“写入”理解成清空、覆盖或更改分享权限。
- 清晰的“把上述结果写入飞书”请求已授权这一次发布，不必重复确认。自动发现本 skill 不代表用户授权自动发布未来的输出。
- 先处理视频、图片或文件中的源内容，再使用本 skill 发布整理后的结果；不要声称此 skill 本身能保证视频识别或像素级复刻。

## 连接与执行

优先使用当前可调用的飞书 MCP 工具。若本轮没有暴露飞书工具，使用 `scripts/feishu.cjs`，它通过已经安装和授权的官方 MCP 执行同样的操作。

**使用辅助脚本前，完整读取 [references/connection.md](references/connection.md)**，确认本机已有连接和私有配置的位置。此仓库不包含密钥、登录状态、个人文档链接或绑定某台电脑的路径。不要为完成写入擅自替换应用或扩大权限。

从实际 skill 所在目录解析脚本路径，不依赖当前工作目录。示例（将脚本和输入文件参数替换为真实路径）：

```text
node <skill目录>/scripts/feishu.cjs inspect <飞书文档链接>
node <skill目录>/scripts/feishu.cjs convert <正文Markdown文件绝对路径>
node <skill目录>/scripts/feishu.cjs schema docx_v1_documentBlockChildren_create
node <skill目录>/scripts/feishu.cjs call docx_v1_documentBlockChildren_create <参数JSON文件绝对路径> --write
```

`inspect`、`convert`、`schema` 和只读 `call` 不修改文档；变更调用必须带 `--write`。`call` 强制使用用户身份。复用官方 MCP 的授权管理，不直接调用接口绕过登录管理。

## 发布流程

1. 读取目标标题并确认文档类型。Wiki 链接先通过 `wiki_v2_space_getNode` 获得 `node.obj_token`；Wiki token 不能直接当作 docx 文档 ID。辅助脚本 `inspect` 会完成这个解析。
2. **第一次实际写入前，完整读取 [references/write-workflow.md](references/write-workflow.md)**，遵循格式转换、创建内容块、表格处理和核对方法。它也说明已验证的 MCP 工具结构限制。
3. 对普通文本、标题、列表、链接等使用文档内容块，而不是把整段 Markdown 当纯文本粘贴。保留用户选择的正文，不默认摘要或重写。
4. 核对新建内容块的文字、结构与目标文档。只有真实读取到预期结果才能报告“已写入”；权限已授予、格式转换成功或版本号改变均不能单独证明发布成功。

辅助脚本不会自动重试写入，每次写入在参数文件旁的 `.feishu-write-receipts` 生成回执，记录幂等标识及结果。超时、断线或部分成功时先核对回执和文档实际内容，不能直接重复整份追加。

## 连接异常与交付

- 路径失效时检查本机连接配置；不展示完整 MCP 配置，也不要求用户将密钥发到聊天中。
- 区分登录授权、应用权限和目标文档编辑权限；只读可访问不代表实际可写。
- 需要重新登录时，使用已有 MCP 的正常登录流程，由用户完成浏览器授权。凭据不得进入 skill、正文、回执或 Git。
- 完成时简短说明已追加或修改的范围，并提供目标文档链接；未核对、部分成功或被阻止时如实说明。
