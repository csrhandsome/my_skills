# 写作政策

## 用哪些格子

| 来源 | 用法 |
|---|---|
| 完成工作 | 只进「这周已做」，写结果 |
| 接收工作里尚未出现在完成工作的项 | 只进「下周待做」，与下周待做去重 |
| 下周待做 | 「下周待做」的主来源；与结转项去重，保留更具体的那条 |

不要把未完成项写进「这周已做」，也不要在「这周已做」里标「跟进中」。

## 归类

按项目/主题合并，不按周一到周五复述。同一主题若本周已完成、下周还要继续，已完成结果进「这周已做」，下一步进「下周待做」。

常用别名见 `config.yaml` 的 `project_aliases`，表里出现新主题就按原文立新类，不要硬塞进旧类。

## 结转

- 接收了但本周没完成 → 下周待做
- 下周待做已覆盖同一主题 → 只保留待做里那条
- 上周待做已完成 → 不要再抄进本周待做

## 事实

- 数字、人名、工期、交付量必须来自粘贴表
- 表里没写「完成」就不要写进「这周已做」
- 空格子当不存在，不要补「无」
- 同一主题在接收/完成/下周待做里出现的链接都要收齐，去重后挂到对应段落
- 不要把无关条目的链接挪过去

## 和行业周报的分工

- 工作两段只来自用户粘贴表
- 行业检索只通过 `embodied-weekly-brief`
- 「和我工作的关系」只解释已有信号和工作焦点的交集，不新增工作项
